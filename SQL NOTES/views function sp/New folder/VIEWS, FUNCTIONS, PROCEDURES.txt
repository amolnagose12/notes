
CONTENTS IN A DATABASE:

	SCHEMAS	:	OBJECTS USED TO GROUP TABLES AND OTHER DATABASE OBJECTS
	TABLES	:	OBJECTS USED TO STORE ACTUAL DATA
	INDEXES :	OBJECTS USED FOR FASTER SEARCH OPERATIONS

	VIEWS	:	OBJECTS USED TO STORE SELECT QUERIES
	FUNCTIONS:	OBJECTS USED TO STORE SELECT & DML QUERIES
	PROCEDURES:	OBJECTS USED TO STORE SELECT, DML, DDL QUERIES
	TRIGGERS:	OBJECTS USED TO STORE & AUTO EXECUTE SELECT, DML, DDL QUERIES


	WHENEVER WE DEFINE A DATABASE, A SET OF SYSTEM OBJECTS [SYSTEM VIEWS, SYSTEM FUNCTIONS, SYSTEM PROCEDURES] ARE AUTO CREATED.
	WE USE THESE SYSTEM OBJECTS FOR AUDIT OPERATIONS.


	VIEWS	:	OBJECTS USED TO STORE SELECT QUERIES
	PURPOSE :	FOR REUSABILITY OF CODE AND TO IMPLEMENT ROW LEVEL SECURITY [RLS]
	SYNTAX	:	CREATE VIEW <VIEW NAME>
			AS
			<< SELECT QUERY >>

	

	FUNCTIONS:	OBJECTS USED TO STORE SELECT & DML QUERIES
	PURPOSE :	FOR COMPUTATIONS or CALCUALTIONS, DATA MODELLING 
	SYNTAX	:	CREATE FUNCTION <FUNCTION NAME>
			RETURN <<DATATYPE>>
			AS
			<< DYNAMIC SELECT QUERY >>


	
	PROCEDURES:	OBJECTS USED TO STORE SELECT, DML & DDL QUERIES
	PURPOSE :	FOR PROGRAMMING, QUERY TUNING OPERATIONS [TUNING : GETTING YOUR QUERY TO EXECUTE BETTER WITH MINIMAL RESOURCES]
	SYNTAX	:	CREATE PROCEDURE <PROCEDURE NAME>
			AS
			<< DYNAMIC SELECT QUERY >> 
			<< PERFORMANCE TUNING OPTIONS >>

















FUNCTIONS	:	DATABASE OBJECTS USED TO STORE DML & SELECT STATEMENTS.
			PURPOSE FOR DEVELOPERS	:	PROGRAMMING, BUSINESS LOGIC IMPLEMENTATION, DATA FORMATTING FOR REPORTS.
			PURPOSE FOR DB ADMINs	:	METADATA AUDITS ++ TO IMPLEMENT RLS : ROW LEVEL SECURITY IN AZURE CLOUD

SYNTAX	:	CREATE FUNCTION <FUNCTION-NAME> (@PARAMETER1 <TYPE>, @PARAMETER2 <TYPE>, PARAMETER3 <TYPE>..)
			RETURNS <<TYPE>
			AS
			BEGIN
			<STATEMENT 1>
			<STATEMENT 2>....
			RETURN <<VALUE>>
			END
																			-- parameters : input values
			TO EXECUTE A FUNCTION:		SELECT <FUNCTION-NAME>  or SELECT * FROM <FUNCTION-NAME>
---------------------------------------------------------------------------------------------------------------------			

STORED PROCEDURES:	DATABASE OBJECTS USED TO STORE ANY TYPE OF T-SQL STATEMENTS.
			PURPOSE FOR DEVELOPERS	:	PROGRAMMING, BUSINESS LOGIC IMPLEMENTATION
			PURPOSE FOR DB ADMINs	:	TUNING USING QUERY OPTIMIZATION TECHNIQUES + METADATA AUDITS

	SYNTAX	:	CREATE PROCEDURE <PROCEDURE-NAME> (@PARAMETER1 <TYPE>, @PARAMETER2 <TYPE>, PARAMETER3 <TYPE>..)
			AS
			BEGIN
			<STATEMENT 1>
			<STATEMENT 2>....
			<<QUERY OPTIMIZATION OPTIONS>>
			END
																		-- parameters : input values
			TO EXECUTE A PROCEDURE:		EXECUTE  <PROCEDURE-NAME>
